# 全カード対戦テスト

Issue #51 の提案93種類（既存25種類＋追加68種類）と従来15種類を登録する。
バランス調整前の対戦検証用として、デッキ編集、CPU、カジュアルPvP、招待PvP、特殊勝利を接続する。

## 利用方法

Discordでログインし、コレクションから各カード最大3枚・合計30枚のデッキを作成する。
「全カードで対戦」（`/battle/test`）でデッキを選択してCPU戦、カジュアル対戦、招待ルームを開始する。
招待コードは12桁、待機期限は10分。CPUのクラスは6クラスから選べる。
複数カードを選ぶ効果では選択順を表示する。矢は装填後も手札に残り、装填順に発射する。
選択待ちは60秒でサーバーが既定選択を確定する。ページを再読み込みしても保存された対戦に復帰する。

Admin判定はN00と同じDiscord OAuthアカウントのOWNER識別を利用する。
クライアントの申告やヘッダーは権限判定に使用しない。コレクション取得・デッキ保存時に
全種類の現在版をデッキ上限まで補充し、N00のAdminActionにAdmin・付与前後の枚数・カード版・理由を保存する。
N00と同様にDiscord認証元が記録されたセッションだけをAdminとして扱うため、
N00導入前のセッションではDiscordで再ログインする必要がある。
過去の専用付与記録もN00監査ログへ移行する。補充済みのカードは再付与・再記録しない。
管理画面は同一ドメインの `/admin/` へ配置する。
MAINTENANCE_MODEでは全カード対戦APIも停止し、ENABLE_PRIVATE_MATCHは新しい招待作成・参加にも適用する。
通常ユーザーには全種類を自動配布しない。パックのレアリティ別抽選対象に追加カードも含める。
`/exchange` では交換ポイントで1枚ずつ交換でき、所持上限は3枚。

| レアリティ | 暫定交換ポイント |
| --- | ---: |
| N | 25 |
| R | 75 |
| SR | 250 |
| SSR | 750 |
| UR | 2500 |

## 保存・再現の契約

新対戦はProtocol 2、engine/rules `3.0.0`、replay format 3を使用する。
従来Protocol 1のランク戦と旧Protocol 2のリプレイは維持する。
ランク戦は全カード対応の対象外で、旧エンジン非対応のデッキは開始時に拒否する。

`AlphaBattle` に初期状態、定義スナップショット、入力ジャーナル、現在状態、再試行受領記録を保存する。
CPUも同じGame Engineで合法手を適用し、クライアントからはカードID・選択・ターン終了等の意図だけを受け取る。
行ロックで操作を直列化し、入力番号で古い画面からの操作を拒否する。
HMAC署名した選択期限・タイムアウトもジャーナルに保存してリプレイで検証する。
初期乱数と敵の手札・山札・カード別修正値はプレイヤー向け応答に出さない。
公開状態、カード移動、装填、コスト変化、特殊勝利をイベントとして記録する。

HTTPの状態取得は1.5秒間隔。全カード対戦の勝敗はこのテスト用対戦テーブルに保存し、
ランク・通常対戦報酬には接続しない。操作上限5000入力に達した場合も投了できる。

## API

全ルートは既存OAuthセッション認証を使用し、変更操作は既存CSRF検証を通す。

| メソッド | パス | 用途 |
| --- | --- | --- |
| POST | `/api/v1/alpha-battles` | CPU / CASUAL / PRIVATE開始 |
| GET | `/api/v1/alpha-battles/active` | 未終了の対戦へ復帰 |
| POST | `/api/v1/alpha-battles/join/:code` | 招待参加 |
| GET | `/api/v1/alpha-battles/:id` | 参加者向け状態・合法手・選択候補 |
| POST | `/api/v1/alpha-battles/:id/actions` | requestId・expectedSequence・action送信 |
| DELETE | `/api/v1/alpha-battles/:id` | ホストの待機取消 |
| GET | `/api/v1/alpha-battles/:id/replay` | 検証済み参加者向けリプレイ |
| GET | `/api/v1/card-exchange` | カタログと交換価格 |
| POST | `/api/v1/card-exchange` | Idempotency-Key付き交換 |

## 運用

本番DBをバックアップし、サービスを停止して `pnpm db:migrate:deploy` を実行する。
続いて本番環境変数を読み込んだ状態で `pnpm --filter @deck-drive/api cards:sync` を実行する。
これは108種類のカード版を追加し、既存定義・ユーザー・所持枚数を上書きしない。
本番で開発用seedやresetを実行しない。
定義変更時はカード版を更新し、過去対戦のスナップショットを維持する。

通常テストはDBなしで実行できる。`pnpm test:integration` は専用PostgreSQLにのみ接続する。
全68種類の効果実行と複合効果、管理者付与、パック入手、交換の同時実行、PvP再接続、CPU終局、
選択期限切れ、Grand Wish特殊勝利、リプレイ検証をカバーする。
ブラウザテストは新しいCPU開始・復帰と交換上限を検証する。
