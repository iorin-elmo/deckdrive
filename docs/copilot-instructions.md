# 重要なルール
- GitHub の PR タイトル・本文・コメントは UTF-8 で記述すること。
- 返答などは基本的に日本語で行うこと
- コードはt wadaのTDDに従って書くこと
- コードの変更は小さく，頻繁に行うこと
- 機能を追加する際は，ブランチを切って作業し，PRをさくせいして，レビューを受けてからマージすること
- コードの品質を保つために，リファクタリングを定期的に行うこと

- 基本はdevelopブランチから分岐させて作業を行うが，大きいリリースが確定したタイミングでmainブランチにマージを行う
- コードの変更履歴は適切にコミットメッセージを記述して管理すること
- コードのレビューは必ず行い，指摘事項があれば修正してからマージすること
- テストコードも必ず作成し，変更が既存の機能に影響を与えていないことを確認すること
- ドキュメントも適宜更新し，コードの変更内容が正しく反映されていることを確認すること
- コードの変更に伴い，必要に応じて依存関係の更新や環境設定の変更も行うこと
- コードの変更に伴い，必要に応じてテスト環境やCI/CDの設定も更新すること

- 基本的にはAIの一人開発になるが，このファイルとIMPLEMENTATION_SPEC.mdを遵守しながら開発を進めていき，機能を追加した際はdocsに知見を残しておくこと．
